# design-direction v1.4: Direction Board + Resume

**Date:** 2026-10-03
**Status:** Approved

## Goals

1. Replace `style-tile.html` with `board.html`, a single page that grows phase by phase:
   Mood (Phase 1) → Spec (Phase 2) → Features (Phase 3).
2. Persist the whole direction so a later session can resume or revise it.

## Files

```
design-direction-<slug>/
├── direction.json             written by Claude: product, mood, features, status
├── tokens.json                written by Claude in Phase 2 (format unchanged)
├── board.html                 generated
├── tokens.css, tailwind.css   generated when tokens.json exists
└── design-direction-<slug>.md generated; the full direction as markdown
```

## direction.json

```json
{
  "product": { "name": "Stillwater", "summary": "…", "audience": "…", "oneWord": "restored", "avoid": "…" },
  "references": ["Aesop", "Kinfolk"],
  "mood": {
    "toneWords": ["quiet confidence", "earned slowness", "warm minimalism"],
    "palettes": [
      { "name": "Warm Stone", "feeling": "…", "direction": "…", "swatches": ["#55705A", "#F7F3EC", "#A65A40"] }
    ],
    "typography": { "personality": "…", "pairing": "…", "heading": "Fraunces", "body": "Inter" },
    "dos": ["…"], "donts": ["…"],
    "manifesto": "…"
  },
  "features": {
    "flows": [ { "name": "Onboarding", "steps": [ { "screen": "Welcome", "purpose": "…" } ] } ],
    "ideas": [ { "name": "…", "what": "…", "why": "…", "effort": "Quick win" } ],
    "interactions": [ { "name": "…", "where": "…", "what": "…", "why": "…", "note": "…" } ]
  },
  "status": { "phase": 2, "approved": [1], "needsReview": [], "log": [ { "date": "2026-10-03", "note": "Mood approved" } ] }
}
```

### Validation

- **product:** `name`, `summary`, `audience`, `oneWord` are required strings. `avoid` is optional.
- **references:** optional array of strings.
- **mood:**
  - `toneWords`: 3–5 strings.
  - `palettes`: 2–3 entries, each with `name`, `feeling`, and 3–5 `#RRGGBB` swatches.
  - `typography`: `heading`, `body`, and `pairing` are required.
  - `dos` and `donts`: at least 1 string each.
  - `manifesto`: required string.
- **features** (optional):
  - If present, it needs at least 1 flow, each with at least 2 steps.
  - Exactly 5 or more ideas, each with an `effort` of `Quick win`, `Medium`, or `Big bet`.
  - At least 3 interactions.
- **status:**
  - `phase` is 1–3.
  - `approved` and `needsReview` are arrays of 1–3.
  - `log` is an optional array.

## Generator

### Inputs

- `node build.js <folder>` reads `direction.json` and, if present, `tokens.json`.
- `node build.js <tokens.json>` still works (v1.3 behavior). It also picks up a sibling
  `direction.json` if one exists.
- With a `direction.json`, missing `tokens.meta.name`, `toneWords`, and `manifesto` are filled in from it
  before validation.

### Outputs

- `board.html` is always written.
- `tokens.css` and `tailwind.css` are written when tokens exist.
- `design-direction-<slug>.md` is written when `direction.json` exists. The slug is the folder name
  without its `design-direction-` prefix.
- `style-tile.html` is no longer written.
- stdout prints the palette and contrast tables when tokens exist, plus a list of the files written.

### Exit codes

Unchanged: 0 = ok, 1 = contrast fail (outputs written), 2 = invalid input (nothing written). An
input is invalid if `direction.json` and `tokens.json` are both missing, or either one is invalid.

## board.html

### Sticky header

- Product name.
- Section nav: Mood · Spec · Features.
- A progress indicator per phase: `approved` ✓, `in review`, `needs review`, or `not started`.
- A light/dark toggle.

### Chrome

- Uses the design's own tokens once `tokens.json` exists.
- Before that, uses a neutral default palette.
- Fonts come from `tokens.font` when present, otherwise from `mood.typography`.

### Mood section

- The manifesto, large.
- Tone-word chips.
- Palette directions as swatch strips with the name, feeling, and hex codes.
- A typography pairing preview in the actual fonts.
- Do's and don'ts columns.
- A brief card showing the audience, product, one word, avoid, and references.

### Spec section

The v1.3 style tile content: swatches, contrast list, type specimen, spacing and radius, components.

### Features section

- Flows as numbered step chains.
- Idea cards with effort badges.
- Interaction cards with a developer note.

### Rules

- Sections not reached yet show a placeholder: "Comes after Phase N approval."
- All user text is HTML-escaped.

## Markdown document

Generated from the same data:

- Title, date, and product brief.
- Mood brief: tone words, palettes with hex swatches, typography, do's and don'ts, manifesto.
- Spec: palette and contrast tables, typography table, spacing, radius, shadows, file list.
- Features: flows, ideas, interactions.
- Revision log.

## Skill flow

### Start

Look for `design-direction-*/direction.json` in the working directory. If one exists and the user
isn't clearly starting a new product: when their intent is already clear ("keep going", a specific
change), act on it after a one-line status recap; when it's ambiguous ("I'm back"), summarize the
status and offer to continue, revise, or start fresh. *(Refined after the first eval run, which showed
that an always-ask rule adds friction when the user has already said "keep going".)*

### Phase 1

1. Run the intake.
2. Write `direction.json` (mood, `status.phase` = 1).
3. Run the build and open `board.html`.
4. Chat shows a compact Mood Brief summary (heading, tone words, palette names, manifesto) and links to
   the board.
5. Ask for approval.

### Phase 2

1. On approval, add 1 to `status.approved` and set `status.phase` = 2.
2. Write `tokens.json` and run the build.
3. Present the tables, open the board, and ask for approval.
4. If `direction.json` is missing (the user arrived with an approved brief), create it from that brief
   first, with `approved` = [1].

### Phase 3

1. On approval, add 2 to `status.approved` and set `status.phase` = 3.
2. Write `direction.features` and run the build.
3. Chat shows a compact summary that links to the board.
4. Ask for approval.

### Closing

On approval, add 3 to `status.approved` and run the build. Point the user to `board.html` and the
generated `.md`.

### Revisions

- Edit the relevant JSON file and run the build again.
- Revising an approved phase adds the later approved phases to `needsReview`.
- Each change appends an entry to `status.log`.

### References

- `references/direction-format.md` is new.
- `tokens-format.md` is unchanged.
- `feature-thinking.md` now describes the `features` JSON plus the chat summary.

## Testing

### Unit tests

- `validateDirection` accepts the fixture and rejects broken fields with useful paths.
- A folder with only `direction.json` builds a board with Mood and placeholders, plus the md, and no
  `tokens.css`.
- Direction plus tokens builds every section and exits 0.
- A v1.3-style `tokens.json` path still builds.
- Progress states render correctly.
- Every new field is escaped.
- The md contains the brief, the tables, and the features.

### Evals

- **phase1-gate:** expects a valid `direction.json` and `board.html`, and no `tokens.json`.
- **contrast-pressure:** expects `board.html`.
- **full-flow:** turn 1 has the board and a `direction.json` with 1 approved; turn 2 regenerates the
  board; turn 3 has at least 5 feature ideas with valid efforts in `direction.json` and 2 approved;
  turn 4 has an md containing a Features section and 3 approved.
- **resume** (new, two turns): seed a Stillwater folder with phases 1–2 approved. "I'm back to work on
  Stillwater" must recognize it, state its status, and offer to continue without writing features or
  restarting the intake. Then "Continue." must write the features and keep the existing approvals.
- **resume-direct** (new): the same seed. "Let's keep going" must recap and go straight to feature
  thinking without restarting the intake. No new folder may be created.
