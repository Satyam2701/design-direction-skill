# design-direction v1.3: Behavioral Evals + Light Split

**Date:** 2026-10-03
**Status:** Approved

## Goals

1. Catch behavior regressions in `SKILL.md` with a local eval suite (`npm run eval`) that runs real
   Claude Code sessions against scenarios.
2. Move rarely-needed detail out of `SKILL.md` into `references/`, keeping each move only if eval pass
   rates don't drop.

## Eval harness

- `evals/run.js` (runner), `evals/scenarios.js` (scenario definitions), `evals/judge.js` (LLM rubric).
  No dependencies.
- CLI: `npm run eval [-- --runs N] [--only <id>]`. Default N = 1.
- **Sandbox per run:** a fresh temp project; the local skill is installed into `.claude/skills/` via
  `bin/install.js`.
- **Isolation:** every `claude` call uses `--setting-sources project --strict-mcp-config`, so the user's
  own skills, plugins, hooks, and MCP servers don't load. `--bare` is not used because it needs an API
  key, while the suite uses the developer's normal Claude Code login.
- **Tools:** `--allowedTools Write Edit Read "Bash(node:*)" "Bash(mkdir:*)" "Bash(ls:*)"` and
  `--disallowedTools "Bash(open:*)" "Bash(xdg-open:*)"`.
- **Multi-turn:** the first turn uses `-p --output-format json`; later turns add `--resume <session_id>`.
- **Checks:** code checks receive `{ text, dir, files }` and reuse `validate()` and `checkContrast()`
  from `build.js`. Judge checks send the transcript and a rubric to `claude -p` (same isolation flags,
  no tools), which must answer `{"pass": boolean, "reason": string}`.
- **Pass rule:** a scenario passes if at least ⌈2N/3⌉ runs pass (1/1 when N = 1). The runner prints a
  table of scenario, pass rate, and failure reasons, and exits 1 if any scenario fails.

## Light split

- Run the eval suite on v1.2 first as the baseline.
- `references/tokens-format.md`: the full tokens.json shape, key rules, meta.copy, and the no-Node
  fallback. SKILL.md keeps the four-step generate flow and says to read this file before writing
  tokens.json.
- `references/feature-thinking.md`: the Phase 3 output template. SKILL.md keeps the Phase 3 gate and
  says to read this file before writing Feature Thinking.
- Re-run the evals. Revert any move whose scenarios drop below the baseline.
- Update the structural tests: markers that moved into a reference file are checked there, and
  SKILL.md must reference each file by path.
