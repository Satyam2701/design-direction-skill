# design-direction v1.2: Style Tile + Design Tokens

**Date:** 2026-10-03
**Status:** Approved
**Approach:** A generator script ships with the skill (approach A)

## Goal

Phase 2 produces a visual style tile and developer-ready token files. All of them are generated from one
`tokens.json`, so the tile shows exactly what developers receive.

## Data flow

```
SKILL.md (Phase 2) → Claude writes design-direction-<slug>/tokens.json
  → node <skill base dir>/scripts/build.js design-direction-<slug>/tokens.json
  → style-tile.html, tokens.css, tailwind.css (written next to tokens.json)
  → stdout: markdown Color Palette table + Contrast Check table
```

### build.js contract

- Single file, no dependencies, runs on Node ≥16. Usage: `node build.js <path/to/tokens.json>`.
- Exit 0: all outputs written and every contrast pair passes.
- Exit 1: outputs written, but one or more contrast pairs fail. Each failing pair is printed to stderr
  as `FAIL <pair> <mode> <ratio> (needs <target>)`.
- Exit 2: tokens.json is invalid (unreadable, bad JSON, missing role, or a color that isn't a hex). Each
  problem is printed to stderr and no outputs are written.
- Exports `contrastRatio(hexA, hexB)`, `validate(tokens)` and `build(tokensPath)` for tests. The CLI
  runs only when the script is invoked directly (`require.main === module`).

## tokens.json format (W3C Design Tokens draft)

```json
{
  "meta": { "name": "Stillwater", "toneWords": ["quiet confidence"], "manifesto": "..." },
  "color": {
    "primary": { "$type": "color", "$value": "#55705A",
                 "$extensions": { "design-direction": { "dark": "#9DB59F" } } }
  },
  "font": {
    "heading": { "$type": "fontFamily", "$value": ["Fraunces", "Georgia", "serif"] },
    "body":    { "$type": "fontFamily", "$value": ["Inter", "system-ui", "sans-serif"] }
  },
  "typography": {
    "h1": { "$type": "typography", "$value": { "fontFamily": "{font.heading}", "fontSize": "48px",
            "fontWeight": 300, "lineHeight": 1.15, "letterSpacing": "0" } }
  },
  "spacing": { "4": { "$type": "dimension", "$value": "4px" } },
  "radius":  { "sm": { "$type": "dimension", "$value": "8px" } },
  "shadow":  { "card": { "$type": "shadow", "$value": "0 2px 8px rgba(0,0,0,0.08)" } }
}
```

**Required color roles** (keys): `primary`, `on-primary`, `secondary`, `accent`, `background`,
`surface`, `neutral-100`, `neutral-300`, `neutral-600`, `neutral-900`, `success`, `warning`, `error`,
`info`. Each must have a light `$value` and an `$extensions["design-direction"].dark` value, both
`#RRGGBB`.

**Required typography styles:** `h1`, `h2`, `h3`, `body`, `caption`, `label`.
**Required fonts:** `heading` and `body`. `spacing`, `radius` and `shadow` must each be non-empty.

### Contrast pairs (checked in both light and dark)

| Pair | Target |
|---|---|
| neutral-900 on background | 4.5 |
| neutral-900 on surface | 4.5 |
| neutral-600 on background | 4.5 |
| on-primary on primary | 4.5 |
| primary on background (focus ring / UI) | 3 |
| accent on background | 4.5, checked only if `meta.accentAsText` is true |

## Outputs

- **tokens.css**: `:root { --color-primary: …; --font-heading: …; --text-h1-size: …; --space-4: …;
  --radius-sm: …; --shadow-card: … }` plus `[data-theme="dark"] { --color-*: dark values }` and an
  equivalent `@media (prefers-color-scheme: dark)` block.
- **tailwind.css**: a Tailwind v4 `@theme { --color-*; --font-*; --spacing-*; --radius-*; --shadow-* }`
  block (light values), plus a dark-mode override block for `[data-theme="dark"]`.
- **style-tile.html**: self-contained. Its only external resource is a Google Fonts link built from the
  first family of each font token (system fallbacks apply offline). Sections: header (name, tone words,
  manifesto); palette swatches (light and dark, hex, contrast badge); type specimen; spacing and radius;
  components (primary, secondary and ghost buttons; input default and focus; card; success, warning,
  error and info alerts); and a light/dark toggle that flips every section.

## Skill flow changes

- **Phase 2:** write tokens.json → run build → on exit 1, adjust lightness (keep hue) and re-run → on
  exit 2, fix the file → paste the printed tables, then add the typography, spacing and component
  notes → open the tile (`open` on macOS, `xdg-open` on Linux, or give the path) → ask for approval.
- **Revisions:** edit tokens.json and re-run the build.
- **Closing:** the final markdown document is saved into the same `design-direction-<slug>/` folder.
- **No Node available:** fall back to the v1.1 behavior. The skill shows the tables with ratios
  labeled "approximate" and hand-writes the HTML and CSS.

## Installer

`bin/install.js` copies the whole `skills/design-direction/` directory (SKILL.md and scripts/)
recursively. It removes the legacy flat-file install as before. The "up to date" check compares every
file.

## Testing

- `test/build.test.js`: `contrastRatio('#000000','#FFFFFF')` = 21. A valid fixture builds all three
  outputs with exit 0, and tokens.css contains the light value, the dark value and `[data-theme="dark"]`.
  A missing role exits 2 and names the role. A failing pair exits 1 and names the pair. The style tile
  contains every role's hex value.
- `test/install.test.js`: the installed folder includes `scripts/build.js`.
- `npm test` runs both test files.
- Live check: run the skill end-to-end in a fresh headless Claude Code session.
