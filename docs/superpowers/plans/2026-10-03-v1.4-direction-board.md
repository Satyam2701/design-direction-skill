# design-direction v1.4 Direction Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `docs/superpowers/specs/2026-10-03-v1.4-direction-board-design.md`.

**Architecture:** Split the 600-line `build.js` into focused modules under `scripts/lib/`. `build.js`
stays the CLI entry point and keeps its current exports, so existing tests and callers still work.

```
scripts/
├── build.js           CLI + build(input): resolve inputs, validate, render, write
└── lib/
    ├── tokens.js      ROLES, TYPE_STYLES, PAIRS, contrastRatio, validate, checkContrast, renderCss,
    │                  renderTailwind, renderTables, font helpers
    ├── direction.js   validateDirection, EFFORTS, phaseState(status, n)
    ├── html.js        esc, googleFontLinks(families)
    ├── board.js       renderBoard({ direction, tokens, results }) → html
    └── markdown.js    renderDocument({ direction, tokens, results, slug }) → md
```

**Tech Stack:** Node ≥16 built-ins only.

## Global Constraints

- No dependencies; `require` paths are relative to `scripts/`, and the installer already copies
  directories recursively.
- Exit codes and the stdout table format are unchanged.
- No attribution trailers in commits.
