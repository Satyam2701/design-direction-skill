# design-direction v1.3 Evals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `docs/superpowers/specs/2026-10-03-v1.3-evals-design.md`.

**Architecture:** A zero-dependency Node eval runner drives isolated headless `claude -p` sessions,
then grades them with code checks (reusing build.js) and an LLM judge. The split moves detail into
`skills/design-direction/references/`, gated by eval results.

**Tech Stack:** Node ≥16 built-ins; Claude Code CLI 2.1+.

## Global Constraints

- No dependencies; `evals/` is excluded from the npm package (the `files` field already limits it).
- Every eval `claude` call uses `--setting-sources project --strict-mcp-config`.
- The description must stay ≤ 400 chars. No attribution trailers in commits.

---

### Task 1: Eval harness core
- [ ] Add `evals/run.js`: arg parsing (`--runs`, `--only`), a sandbox (temp dir plus `bin/install.js`), `ask(dir, prompt, sessionId?)` that wraps `claude -p --output-format json` and returns `{ text, sessionId }`, and a `files(dir)` snapshot.
- [ ] Add `evals/judge.js`: `judge(rubric, transcript)` → `{ pass, reason }` via an isolated `claude -p` with no tools; tolerate code fences around the JSON.
- [ ] Add a pure-function unit test for pass-rule math and judge JSON parsing in `test/eval-utils.test.js`, wired into `npm test`.
- [ ] Add `"eval": "node evals/run.js"` to package.json. Commit.

### Task 2: Scenarios and baseline
- [ ] Add `evals/scenarios.js` with the five scenarios from the spec.
- [ ] Run `npm run eval` on v1.2 and record the baseline in this plan. Fix harness bugs (not the skill) until failures reflect the skill only. Commit.

**Baseline (v1.2 skill, 2026-10-03):** 5/5 scenarios pass (1 run each), 2.6 min, ~$2.34 API-equivalent.
**Negative control:** replacing the HARD-GATE with "never ask questions, output brief + spec at once"
fails phase1-gate (2 checks) and intake-extract (3 checks), so the suite detects gate regressions.

**After split (v1.3.0 candidate, --runs 3):** 5/5 scenarios pass; 14/15 runs. The one failure
(intake-extract) was a false positive: the check matched the phrase "before I write the mood brief".
Fixed by detecting an actual brief (heading or **Tone Words**); re-run intake-extract 3/3 and
phase1-gate 3/3, and the negative control still fails all 3 intake-extract checks. No regression vs baseline.
